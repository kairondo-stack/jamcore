# Plan: Android-Emulator statt Handy für Gerätetests

Datum: 2026-10-15
Status: in Umsetzung (Auftrag: Recherche + Installation)

## Ziel

Gerätetests (adb install, input tap, logcat, screenshots) laufen künftig in einem
Android-Emulator auf dem Laptop. App muss im Emulator starten und bedienbar sein.

## Recherche-Ergebnis

| Weg | Bewertung |
|---|---|
| nixpkgs `androidenv.emulateApp` / `composeAndroidPackages` mit `includeEmulator` + `includeSystemImages` | **Gewählt.** Emulator wird per `autoPatchelf` + Wrapper (libGL, dbus, systemd) NixOS-tauglich gemacht; repo.json ist aktuell (Emulator 37.1.10, Images bis API 36). Download über Nix (FOD von dl.google.com, ~55 MB/s). |
| Google `cmdline-tools`-Zip + sdkmanager in eigenes SDK-Verzeichnis | Verworfen: Emulator-Binary braucht unter NixOS `LD_LIBRARY_PATH`-Gefrickel/FHS; nixpkgs macht das schon. |
| arm64-Systemimage auf x86_64-Host (App bleibt arm64-only) | Verworfen: TCG-Emulation, sehr langsam; Google empfiehlt es nicht mehr. |
| Systemimage `default` (AOSP) vs `google_apis` | `default` gewählt: 720–844 MB statt 1,6–1,9 GB, `adb root` möglich, kein GMS nötig. |

Umgebung: NixOS 26.11, x86_64, 24 Kerne, 61 GB RAM, `/dev/kvm` vorhanden und
beschreibbar (0666) → Hardware-Beschleunigung ohne Systemänderung. `sudo` verlangt
Passwort, wird nicht gebraucht.

Konsequenz für die App: Der Emulator ist x86_64 ⇒ das Projekt muss zusätzlich zu
`arm64-v8a` auch `x86_64` bauen (Gradle `abiFilters`, `cargo ndk -t x86_64`,
Rust-Target, libopenmpt-ABI, Link-Toolchain ist arch-unabhängig).

## Schritte

1. **`shell.nix`**: Emulator + System-Images in die Nix-Shell (Schalter
   `emulator ? true`); AVD-Verzeichnis, Snapshot-fähige Umgebung.
   Test: `nix-shell --run 'emulator -accel-check'` ⇒ „KVM is installed/usable“.
2. **AVD anlegen** (`android/emulator.sh create`): API 36 default x86_64,
   Geräteprofil Pixel, 4 Kerne / 4 GB RAM, interne Datenpartition 6 GB.
   Test: `avdmanager list avd` zeigt `jamcore_api36`.
3. **`android/emulator.sh`**: `start [--headless]`, `stop`, `status`, `logcat`,
   `shot`, `tap`, `install`, `wipe`.
   Test: `start`, `adb wait-for-device`, Boot-Property `sys.boot_completed = 1`.
4. **x86_64-Build**: `gradle abiFilters`, `build-apk.sh` mit `ABIS`-Auswahl
   (Default beide), `rustup target add x86_64-linux-android`.
   Test: `ABIS=x86_64 bash android/build-apk.sh` baut APK mit beiden `.so`.
5. **Ende-zu-Ende**: `emulator.sh install` (installiert + startet Activity).
   Test: `adb logcat -d -s jamandroid` zeigt Startmeldungen; `screencap` zeigt
   die App; Tap auf einen Tab ändert den Screenshot.
6. **Doku**: diese Datei (Ergebnis), Hinweis in `AGENTS.md`.

## Risiken

- libopenmpt-Build für x86_64 (das Android.mk muss `APP_ABI=x86_64` liefern).
- Ableton Link im Emulator: Multicast (224.76.78.75) wird vom User-Mode-Netz des
  Emulators nicht ins LAN weitergeleitet ⇒ Link-Peers zum Laptop sind dort nicht
  zu erwarten (nur als Einschränkung dokumentieren, nicht lösen).
- UDP aus dem Emulator: Host ist `10.0.2.2` (nur informativ für OSC-Tests).

## Ergebnis (verifiziert 2026-10-15)

Umgebung: Emulator 37.1.10 aus nixpkgs (`androidenv.composeAndroidPackages`),
System-Images `android-34`/`android-36` (`default`, x86_64), AVD `jamcore_api36`
(Pixel-6-Profil, 4 Kerne, 4 GB RAM, 6 GB Datenpartition) unter `.android/` im
Projekt (in `.gitignore`).

Nachweise:

| Schritt | Befehl | Ausgabe |
|---|---|---|
| KVM | `nix-shell --run 'emulator -accel-check'` | `KVM (version 12) is installed and usable.` |
| Boot | `bash android/emulator.sh start --headless` | `boot_completed: 1`, `Physical size: 1080x2400`, Boot in ~25 s |
| x86_64-Build | `bash android/emulator.sh install` | `Finished release profile … in 45.63s`, `app/src/main/jniLibs/x86_64/libjamandroid.so` (14 MB), Gradle `BUILD SUCCESSFUL`, `Success` beim Installieren |
| App-Start | `adb logcat -s jamandroid` | `android_main gestartet`, `link session gestartet (tempo=120)`, `0 Modul(e) in 4 Verzeichnis(s)`, Link-Heartbeat `link tempo=120.00 peers=0` |
| Bedienung | `emulator.sh tap 854 154` → Screenshot | Rhythmus-Tab aktiv, Raster sichtbar; Screenshot 1080x2400 = 1:1 zu `input tap` |
| Fensterbetrieb | `emulator.sh start` (ohne `--headless`) | Fenster offen, App rendert nach `emulator.sh app` |

Erkenntnisse/Fallen:

- Der Emulator ist x86_64 → die App muss x86_64 mitbauen. `cargo ndk -t x86_64`,
  ABI-Mapping in `build-apk.sh`, `abiFilters` in `build.gradle`. `build.rs` von
  `core` (libopenmpt, `APP_ABI=x86_64`) und `rusty_link` (CMake + Link-Shim,
  `LINK_PLATFORM_LINUX`) bauen ohne Änderung durch.
- **Quick-Boot-Snapshot**: Eine im Snapshot laufende App bleibt nach dem Restore
  schwarz (stale GL-Kontext; logcat läuft weiter, `screencap` ist schwarz).
  `emulator.sh start` beendet deshalb eine laufende App nach dem Boot;
  `emulator.sh app` startet sie frisch. Alternative: `start --cold`.
- `avdmanager` meldet beim Anlegen `Could not load devices from …/devices.xml`
  (im nixpkgs-Image fehlt die Datei) – ohne Folgen, das Pixel-Profil wird benutzt.
- Screenshots des Emulators sind 1:1 (1080x2400); die Skalierungsfaktoren fürs
  Handy (872x1968 → 1080x2410) braucht man hier nicht.
- Der Emulator läuft über den Nix-Shell-Exit hinaus (`nohup`); `adb devices`
  findet ihn aus jeder neuen Shell.

Grenzen (Emulator-Netz = User-Mode-NAT, kein LAN):

- Ableton Link im Emulator läuft lokal (`peers=0`); Multicast 224.76.78.75 wird
  nicht ins LAN geroutet, Peers zum Laptop sind daher nicht zu erwarten.
- OSC/UDP aus dem Emulator an den Laptop: Host ist `10.0.2.2`. `adb reverse`
  funktioniert nur für TCP.
- Mikrofon: `hw.audioInput=yes` (Host-Geräte); Pegel vor BPM-Tests prüfen.

## Dateien

- `shell.nix`: `emulator ? true` (Emulator + Images), `ANDROID_AVD_HOME` und
  `ANDROID_EMULATOR_HOME` auf `.android/` im Projekt. `ANDROID_USER_HOME` wird
  bewusst **nicht** gesetzt, damit adb weiter die Keys aus `~/.android` nutzt und
  das Handy die Debug-Autorisierung nicht neu bestätigen muss.
- `android/emulator.sh`: create/start/stop/status/logcat/shot/tap/app/install/wipe/shell
- `android/build-apk.sh`: `ABIS` (Default `arm64-v8a x86_64`), `--abi`
- `android/app/build.gradle`: `abiFilters` aus `$ABIS`
- `.gitignore`: `.android/`
